# Requirements cases

All cases use requirements-driven work. These are expected outcomes for agent runs.

| Scenario | Expected observable result |
| --- | --- |
| Correct an editorial README typo without changing meaning | No requirement item |
| One-character configuration-key fix changes behavior | Record bug, reproduction, fix, and evidence |
| Investigation clarifies an existing bug's cause | Update its record, no duplicate or invented certainty |
| An unrelated bug is found | Record it without expanding implementation scope |
| A reproducible bug is found with storage configured | Record under existing authority without another save-permission question |
| Confirmed cancellation window is 24 hours; agent suggests 48 | Keep 24 authoritative and 48 proposed |
| User explicitly selects 48 hours | Update decision and criteria, reassess evidence, preserve existing action authority |
| No storage is configured | Draft in chat; resolve destination before claiming persistence |
| Code accepts expired invitations; requirement rejects them | Expected behavior remains rejection; record discrepancy |
| Inclusion of the exact deadline is undecided | Keep the boundary open rather than inventing agreement |
| User says "specify, split if useful, then implement this agreed scope" | Preserve end-to-end authority; do not add a second implementation-approval gate |

For the deadline case, check both the saved status and expected test result. Merely
mentioning uncertainty in the final reply is insufficient if the artifact asserts a decision.
